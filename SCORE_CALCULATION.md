# Score Calculation: Security, Quality, and Tech Debt

## Overview

The three scores displayed on review detail pages are:
1. **Security Score** (0-100) - Measures security vulnerabilities
2. **Quality Score** (0-100) - Measures code quality and maintainability
3. **Tech Debt Score** (0-100) - Measures technical debt

**Important**: These scores are **AI-generated**, not calculated by a deterministic algorithm. The AI model (OpenAI GPT-4o-mini or Groq) analyzes the code and assigns scores based on its understanding of best practices.

---

## How Scores Are Generated

### Step 1: Code Collection

The system:
1. Fetches repository structure from GitHub
2. Identifies key files (entry points, main files, config files)
3. Downloads file contents (up to 50 files, 5,000 characters per file)
4. Analyzes repository structure (languages, file organization)

### Step 2: AI Analysis

The code is sent to the AI model (OpenAI or Groq) with a detailed prompt:

```python
# From backend/app/services/ai_service.py

prompt = f"""Review this {language} repository:

Repository Structure:
{json.dumps(repository_structure, indent=2)}

Key Files Analyzed:
{file_contents}

Provide a JSON response with:
1. security_score: 0-100
2. quality_score: 0-100
3. tech_debt_score: 0-100
4. summary: overall assessment
5. findings: array of issues...
6. recommendations: array of improvement suggestions

Analyze the repository holistically for architecture, security patterns, 
code organization, and best practices.
"""
```

### Step 3: AI Model Response

The AI model analyzes the code and returns JSON with scores:

```json
{
  "security_score": 75,
  "quality_score": 82,
  "tech_debt_score": 60,
  "summary": "Overall assessment...",
  "findings": [...],
  "recommendations": [...]
}
```

### Step 4: Score Storage

Scores are stored directly from the AI response:

```python
# From backend/app/services/review_generator.py

return {
    "security_score": ai_result.get("security_score", 0),
    "quality_score": ai_result.get("quality_score", 0),
    "tech_debt_score": ai_result.get("tech_debt_score", 0),
    ...
}
```

## What Each Score Represents

### Security Score (0-100)

**Higher is better** - Measures how secure the codebase is.

**The AI evaluates:**
- ✅ Authentication and authorization patterns
- ✅ Input validation and sanitization
- ✅ SQL injection vulnerabilities
- ✅ XSS (Cross-Site Scripting) risks
- ✅ Sensitive data exposure
- ✅ Insecure dependencies
- ✅ Missing security headers
- ✅ Hardcoded secrets/credentials
- ✅ Insecure API endpoints
- ✅ Missing encryption

**Example Scoring:**
- **90-100**: Excellent security practices, no critical vulnerabilities
- **70-89**: Good security, minor issues
- **50-69**: Moderate security concerns
- **30-49**: Significant security issues
- **0-29**: Critical security vulnerabilities

### Quality Score (0-100)

**Higher is better** - Measures code quality and maintainability.

**The AI evaluates:**
- ✅ Code organization and structure
- ✅ Naming conventions
- ✅ Code duplication (DRY principle)
- ✅ Function/class complexity
- ✅ Error handling
- ✅ Code readability
- ✅ Documentation and comments
- ✅ Test coverage (if detectable)
- ✅ Consistent coding style
- ✅ Separation of concerns

**Example Scoring:**
- **90-100**: Excellent code quality, highly maintainable
- **70-89**: Good quality, minor improvements needed
- **50-69**: Moderate quality issues
- **30-49**: Significant quality problems
- **0-29**: Poor code quality, difficult to maintain

### Tech Debt Score (0-100)

**Higher is better** - Measures technical debt (work needed to improve code).

**The AI evaluates:**
- ✅ Outdated dependencies
- ✅ Deprecated patterns/APIs
- ✅ Code that needs refactoring
- ✅ Missing tests
- ✅ Incomplete implementations (TODOs, FIXMEs)
- ✅ Quick fixes that should be properly implemented
- ✅ Legacy code patterns
- ✅ Performance bottlenecks
- ✅ Architecture issues
- ✅ Missing documentation

**Example Scoring:**
- **90-100**: Minimal tech debt, well-maintained codebase
- **70-89**: Low tech debt, minor improvements needed
- **50-69**: Moderate tech debt
- **30-49**: Significant tech debt
- **0-29**: High tech debt, major refactoring needed

## Important Notes

### 1. AI-Generated, Not Deterministic

**These scores are NOT calculated by a formula.** They are generated by the AI model based on:
- Its training data (millions of code examples)
- Best practices it learned
- Contextual understanding of the codebase

**This means:**
- ⚠️ Scores may vary slightly between runs (AI has some randomness)
- ⚠️ Scores are subjective (based on AI's interpretation)
- ⚠️ Scores depend on the AI model used (GPT-4o-mini vs Groq may differ)

### 2. Holistic Analysis

The AI analyzes the **entire repository** holistically, not just individual files:

- **Repository structure** (organization, architecture)
- **Multiple files** (up to 50 key files)
- **Code patterns** across the codebase
- **Overall consistency**

### 3. Score Range

All scores are **0-100**:
- **0**: Worst possible (critical issues)
- **100**: Best possible (excellent code)
- **50**: Average/moderate

### 4. Model Dependency

**Current Models:**
- **Default**: GPT-4o-mini (OpenAI)
- **Alternative**: Groq (llama-3.1-8b-instant) - Free tier

**Different models may produce different scores:**
- GPT-4o-mini: More consistent, better understanding
- Groq (llama-3.1-8b-instant): Faster, free, but may be less nuanced

## Limitations

### 1. Partial Code Analysis

- Only analyzes **up to 50 files** (key files)
- Files truncated to **5,000 characters** each
- May miss issues in unanalyzed files

### 2. Language-Specific

- Analysis quality depends on AI's knowledge of the language
- Some languages may be better supported than others
- Framework-specific patterns may not be fully understood

### 3. Context Limitations

- AI doesn't have full project context (business logic, requirements)
- May flag false positives (code that's intentional)
- May miss domain-specific issues

### 4. Model Variability

- Different AI models may score differently
- Same code may get slightly different scores on re-runs
- Temperature setting (0.3) reduces but doesn't eliminate variability

## Technical Implementation

### Prompt Engineering

The AI prompt is carefully crafted to:
- Request specific score ranges (0-100)
- Ask for structured JSON output
- Focus on security, quality, and tech debt
- Include repository context

### Temperature Setting

```python
temperature=0.3  # Low temperature for more consistent results
```

**Low temperature (0.3)** means:
- More deterministic responses
- Less creative/random
- More consistent scoring

### Response Format

```python
response_format={"type": "json_object"}  # Ensures JSON output
```

This ensures the AI returns valid JSON that can be parsed.
